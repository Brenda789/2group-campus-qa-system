一、今日工作内容

今日主要完成了校园智能问答系统的前后端联调开发工作，具体包括以下功能模块：

1. 访客会话管理模块

实现了未登录用户以访客身份使用问答系统的完整流程。访客打开页面后自动获取访客身份令牌，可正常进行提问和文档上传，问答记录存入数据库。关闭或刷新页面时，后端自动清理该访客的所有关联数据（问答记录、会话、消息、上传文档、访客身份）。

2. 文档隔离模块

为知识库文档表新增 visibility（可见性）字段，支持 PUBLIC 和 PRIVATE 两种模式。用户上传的文档默认私有，仅上传者可见。RAG 问答引擎在检索时按用户过滤可见文档。

3. 管理员权限优化

修复管理员不能停用/删除自己账号的校验逻辑（前后端双重保护）；用户删除从软删除改为硬删除（直接从数据库移除）；管理员可以删除其他管理员，但不能删除自己；管理员可以重置其他用户密码为 "admin123"。

4. 个人管理页面

在管理后台侧边栏新增"个人管理"入口，用户可以修改自己的登录密码（需验证旧密码）和邮箱地址。

5. 问答记录管理

管理后台的"问答记录"页面改为仅显示当前用户自己的记录，支持查看详情和删除操作。删除时校验记录归属。

6. 文档拖拽上传

首页浮动上传弹窗和知识库管理页面均改为拖拽式上传（Upload.Dragger），支持将文件拖拽至上传区域或点击选择文件。

7. 登录/注册表单优化

登录页密码框去掉最小长度提示；注册页密码规则简化为仅需大于6位，去掉正则复杂校验。

二、遇到的困难

困难1：前端 axios 拦截器不读取 sessionStorage

访客 token 存储在 sessionStorage（关闭标签页自动清除），但 axios 请求拦截器仅从 localStorage 读取 token，导致所有访客 API 请求不带 Authorization 头，后端无法识别访客身份，前端显示"（模拟回答）后端服务暂时不可用"。

困难2：数据库缺失列导致 SQL 异常

qa_record 表缺少 conversation_id 列，QaService.ask() 方法中 updateById(record) 回写 conversationId 时触发 SQLSyntaxErrorException: Unknown column 'conversation_id'。同样 kb_document 表缺少 visibility 列导致 MyBatis-Plus 查询报错。

困难3：刷新页面的竞态条件

用户在页面关闭/刷新时通过 beforeunload 事件发送 DELETE 请求删除访客数据，但 sessionStorage 在刷新后仍然保留旧 token。新页面加载后使用已被删除的访客 token，导致 INSERT qa_record 时外键约束失败（user_id 对应的 sys_user 记录不存在）。

困难4：RAG 检索找不到答案

visibility 列新增后所有已有文档默认值为 PRIVATE，getVisibleDocumentIds() 返回空集合，向量搜索将全部文档切片过滤掉，导致 LLM 每次返回"该问题暂时无法从知识库中找到答案"。

三、解决方案

解决1：修复 axios 拦截器

修改 request.ts 中的请求拦截器，改为同时读取 localStorage 和 sessionStorage：

图1 修复 axios 拦截器读取双存储 — request.ts

// 修改前：仅读取 localStorage
const token = localStorage.getItem('token')

// 修改后：同时读取两种存储
const token = localStorage.getItem('token') || sessionStorage.getItem('token')

解决2：DatabaseInitializer 自动补齐缺失列

在应用启动时通过 DatabaseInitializer 组件的 @PostConstruct 方法，使用三层回退策略（ALTER TABLE ADD COLUMN IF NOT EXISTS → information_schema 检查 → 直接 ALTER TABLE 忽略重复错误）自动添加 conversation_id、feedback、visibility 等列。同时调整 QaService.ask() 逻辑，先创建会话再保存问答记录，避免事后 UPDATE。

图2 DatabaseInitializer 自动补齐列 — DatabaseInitializer.java

解决3：修复竞态条件

在 beforeunload 回调中，先从 sessionStorage 取出 token 存入闭包变量，然后立即清除 sessionStorage，最后再用闭包中的 token 发送 DELETE 请求。这样新页面加载时 sessionStorage 为空，自动获取全新访客身份，不会引用已删除的旧 token。同时在 ChatController.ask() 中增加用户存在性校验，如果 token 对应的 userId 不存在则自动重建访客。

图3 修复竞态条件 — HomePage.tsx beforeunload 处理

const guestToken = window.sessionStorage.getItem('token')
// 关键：先清 sessionStorage，再发请求
window.sessionStorage.removeItem('token')
window.sessionStorage.removeItem('user')
fetch('http://localhost:8000/api/auth/guest', {
  method: 'DELETE',
  headers: { 'Authorization': `Bearer ${guestToken}` },
  keepalive: true,
})

解决4：RAG 可见性过滤问题

将 RagService.getVisibleDocumentIds() 方法临时改为直接返回 null（null 在向量搜索中表示"不过滤"），恢复原有搜索行为。同时在 DatabaseInitializer 中增加 UPDATE 语句将已有文档批量设为 PUBLIC，确保向后兼容。

图4 RAG 可见性过滤兜底 — RagService.java

四、业务模块设计逻辑

4.1 访客会话生命周期

访客用户的生命周期管理采用"即时创建 + 定时清理"策略：

（1）创建阶段：访客首次发起 API 请求时，ChatController 检测到无 userId，自动调用 SysUserService.createGuestUser() 创建临时用户（角色=guest），生成 JWT token 随响应返回给前端。前端将 token 存入 sessionStorage。

（2）使用阶段：访客和登录用户使用相同的问答接口（/api/chat/ask），后端通过 JWT 解析区分身份。访客的问答记录正常存入 qa_record 表，上传的文档标记 is_temporary=true。

（3）清理阶段：页面关闭/刷新时，beforeunload 事件触发 DELETE /api/auth/guest，后端 cleanupGuestUser() 级联删除该访客的问答记录→会话→消息→文档文件+向量索引→用户本身。同时 GuestCleanupTask 定时任务每30分钟清理超过1小时的过期访客作为安全网。

图5 访客创建与清理的核心代码 — SysUserService.java

@Transactional
public Map<String, Object> createGuestUser() {
    // 生成随机访客账号
    String username = "guest_" + UUID.randomUUID().toString().substring(0, 8);
    SysUser user = new SysUser();
    user.setUsername(username);
    user.setRole("guest");
    user.setStatus(1);
    save(user);
    // 生成JWT并返回
    String token = jwtUtil.generateToken(user.getId(), username, "guest");
    return Map.of("token", token, "userId", user.getId(), ...);
}

图6 问答接口自动创建访客 — ChatController.java

@PostMapping("/ask")
public Result<QaRecord> ask(@Valid @RequestBody ChatRequest req, HttpServletRequest request) {
    Long userId = (Long) request.getAttribute("userId");
    // 校验用户是否存在（防竞态）
    if (userId != null && sysUserService.getById(userId) == null) userId = null;
    // 无有效userId时自动创建访客
    if (userId == null) {
        Map<String, Object> guest = sysUserService.createGuestUser();
        userId = (Long) guest.get("userId");
        guestToken = (String) guest.get("token");
    }
    QaRecord record = qaService.ask(userId, req.getQuestion(), req.getConversationId());
    if (guestToken != null) record.setGuestToken(guestToken);
    return Result.success(record);
}

4.2 文档权限模型

文档可见性采用二值模型：PUBLIC（所有人可用）和 PRIVATE（仅上传者可用）。用户上传的文档默认 PRIVATE。RAG 检索时，将 PUBLIC 文档 ID 集合 + 当前用户上传的 PRIVATE 文档 ID 集合传入向量搜索引擎进行过滤。前端知识库管理页面统一过滤为仅显示当前用户上传的文档。
